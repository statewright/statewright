### Fresh observations

- Read the installed renderer asset and independently computed the same
  `c723a7c8704cc5ffd2d989d920adc942aae4599c6ec8d440f3bdd97a50126fd6` SHA-256.
  Ran six cases against only its isolated pure reducer in a code-generation-

  Starting paused (`prework_watch` or `static`) remains `prework_watch` in both
  sequences. This supports the graceful-completion hypothesis; it does not
  prove actual renderer event/render scheduling or visible scrolling.
- Built an opt-in prototype with authenticated hook acknowledgements, a
  summary-only pre-tool gate, real terminal waiting, route/state revalidation,
  cancellation, and hard-interrupt fallback. Dedicated WebSocket fixtures:
  **26 passed, zero failed, one opt-in native canary skipped**. These fixtures
  acknowledge hooks directly over HTTP; they do not prove native hook delivery.
- Independent non-editing review `graceful_handoff_review` found three gating
  defects: (1) waiting for an absent hook leaves an unguarded grace window;
  (2) an ACK without the matching native lifecycle event can deny tools
  indefinitely because its timeout has no consumer; (3) hook coverage cannot
  enforce a complete no-tools boundary. The reviewer reproduced (2) with
  20 ms deadlines: after 200 ms there was still no interrupt or successor.
- Current [official hook documentation](https://learn.chatgpt.com/docs/hooks)
  explicitly excludes hosted tools and subsequent `write_stdin` input/polls
  from PreToolUse coverage, and warns that specialized paths can opt out.
  PostToolUse `continue: false` replaces the result and continues the model;
  it does not provide the required finish-without-tools boundary.
- [App Server documentation](https://learn.chatgpt.com/docs/app-server) describes
  `turn/steer` as input steering without turn-level overrides. Reading the
  previously generated native schema corroborated that there is no tools or
  tool-choice field on TurnSteerParams, and thread setting overrides apply to
  subsequent turns. That schema was inherited evidence, not regenerated here.
